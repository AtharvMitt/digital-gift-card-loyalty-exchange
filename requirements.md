
# Requirements Table

| ID      | Type                   | Description                                                                                                                                                            | Priority | Acceptance Criteria                                                                                                                                                                                                               | Rationale                                                                                            |
| ------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| FR-001  | Functional             | The system shall validate loyalty points submitted by an Account Holder against the corresponding Merchant Partner's records before allowing conversion.               | High     | Pass: Valid and available loyalty points are accepted for conversion. Fail: Invalid, expired, or insufficient points are rejected.                                                                                                | Validation prevents unauthorized or invalid points from entering the exchange system.                |
| FR-002  | Functional             | The system shall convert validated loyalty points into universal exchange credits using the currently applicable dynamic conversion rate.                              | High     | Pass: Valid points are converted using the current conversion rate and the resulting credit balance is updated. Fail: Conversion is rejected when the points are invalid or the conversion rate is unavailable.                   | Users need a common exchange unit to redeem gift cards across participating merchants.               |
| FR-003  | Functional             | The system shall display the applicable point-to-credit conversion rate and the Account Holder's available universal exchange credit balance before redemption.        | Medium   | Pass: The current conversion rate and available balance are displayed correctly. Fail: Redemption information is not displayed when the required wallet data is unavailable.                                                      | Account Holders need accurate conversion and balance information before making redemption decisions. |
| FR-004  | Functional             | The system shall allow an Account Holder to redeem available universal exchange credits for an eligible digital gift card.                                             | High     | Pass: A valid redemption request with sufficient credits creates a gift-card voucher. Fail: Redemption is rejected when the Account Holder has insufficient credits or the requested gift card is unavailable.                    | Gift-card redemption is a core purpose of the digital wallet platform.                               |
| FR-005  | Functional             | The system shall generate a unique single-use digital voucher code and lock the voucher against duplicate redemption.                                                  | High     | Pass: A unique voucher with a cryptographic checksum is generated and can be redeemed only once. Fail: An expired or previously redeemed voucher is rejected.                                                                     | Single-use voucher locking prevents duplicate redemption and reduces fraud.                          |
| NFR-001 | Performance & Security | Point conversion and gift card redemption operations shall complete within 250 ms under the defined normal operating load while maintaining zero ledger balance drift. | High     | Pass: Benchmarking tests demonstrate that the operations complete within 250 ms and wallet balances remain consistent under simulated peak load. Fail: The latency target is exceeded or any ledger balance inconsistency occurs. | Fast processing and accurate financial records are essential for a trustworthy exchange platform.    |
| NFR-002 | Security               | The system shall protect digital voucher codes against unauthorized reuse, tampering, and fraudulent redemption.                                                       | High     | Pass: Tampered, expired, or previously redeemed vouchers are rejected and valid vouchers can be redeemed only once. Fail: A modified or previously redeemed voucher is accepted.                                                  | Strong voucher protection is necessary to prevent fraud and financial loss.                          |
